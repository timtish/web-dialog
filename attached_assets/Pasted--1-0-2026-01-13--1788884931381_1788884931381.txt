# Фича: Закладки с персонажами **Версия:** 1.0 **Дата:** 2026-01-13 **Статус:** Дополнение к основному ТЗ (v3) --- ## 1. Концепция Отец может создавать "закладки" — ИИ-собеседников в стиле реальных людей (писателей, актёров, исторических фигур). Переключение происходит в одном чате (не отдельные сессии). --- ## 2. UI-расположение **Правая колонка** (под погодой и "умной мыслью"): ``` ┌─────────────────────────────────┐ │ СЕГОДНЯ │ │ +8° │ │ пасмурно, но тепло │ │ Тула · вторник │ └─────────────────────────────────┘ ┌─────────────────────────────────┐ │ 🌿 «Хороший разговор — │ │ это тоже прогулка» │ │ маленькая мысль на сегодня │ │ (соответствует выбранному │ │ персонажу) │ └─────────────────────────────────┘ ┌─────────────────────────────────┐ │ СОБЕСЕДНИКИ │ │ │ │ 🎭 По умолчанию (активен) │ │ 📜 Сергей Есенин │ │ 🎩 Шерлок Холмс │ │ 🧙 Гэндальф │ │ │ │ [+ Добавить нового] │ └─────────────────────────────────┘ ``` **Основная область чата** — без изменений (одно поле ввода, история сообщений). --- ## 3. Логика создания закладки ### 3.1. Пользовательский сценарий 1. Отец кликает "Добавить нового" 2. Появляется модальное окно: "Опишите нового ИИ-собеседника" 3. Примеры подсказок: "Сергей Есенин, поэт, говори поэтично про природу", "Шерлок Холмс, детектив, используй дедукцию" 4. Отец вводит описание, нажимает "Создать" 5. Backend: - Вызывает Yandex Search API с запросом (например, "Сергей Есенин биография стиль речи произведения") - Получает контекст (snippet + URL) - Отправляет в LLM: "Создай system prompt для ИИ-собеседника на основе контекста. Описание пользователя: [описание]. Контекст: [результаты поиска]. Формат: краткий, 200-300 слов, тон и стиль речи." - Сохраняет результат в файл `prompts/персонаж_01.md` (нумерация автоматическая) - Добавляет закладку в список 6. UI обновляется, новый персонаж появляется в списке ### 3.2. Структура файла промпта `prompts/персонаж_01.md`: ```markdown # Сергей Есенин ## Описание Ты — Сергей Есенин, русский поэт начала XX века. Говори поэтично, используй образы природы, деревни, России. Обращайся к собеседнику тепло, как к другу. ## Стиль речи - Короткие, образные фразы - Метафоры про природу (берёзы, поля, закаты) - Иногда вставляй строки из своих стихов (если уместно) - Не используй современные слова (интернет, телефон) ## Запреты - НЕ говори про пьянство и дебоши - Если речь заходит об алкоголе — мягко отговаривай, скажи "я сам ошибался, не повторяй" - НЕ романтизируй свою раннюю смерть ## Темы для разговора - Природа, деревня, Россия - Любовь, дружба - Поэзия, творчество - Воспоминания о юности ``` ### 3.3. Хранение закладок Файл `bookmarks.json`: ```json { "bookmarks": [ { "id": "default", "name": "По умолчанию", "icon": "🎭", "prompt_file": null, "created_at": "2026-01-13T12:00:00" }, { "id": "esenin", "name": "Сергей Есенин", "icon": "📜", "prompt_file": "prompts/персонаж_01.md", "created_at": "2026-01-13T14:30:00" }, { "id": "sherlock", "name": "Шерлок Холмс", "icon": "🎩", "prompt_file": "prompts/персонаж_02.md", "created_at": "2026-01-13T15:00:00" } ], "active_bookmark": "default" } ``` --- ## 4. Логика переключения персонажей ### 4.1. Переключение 1. Отец кликает на персонажа в списке 2. Backend: - Обновляет `active_bookmark` в `bookmarks.json` - Если у персонажа есть `prompt_file` — читает его - Заменяет system prompt в текущей сессии - Генерирует "умную мысль" под нового персонажа (см. 4.2) 3. UI обновляется: активный персонаж подсвечен, "умная мысль" меняется ### 4.2. "Умная мысль" под персонажа - При переключении (или при загрузке страницы) backend вызывает LLM: ``` System: [system prompt персонажа] User: "Сгенерируй короткую мудрую мысль (1-2 предложения) в стиле этого персонажа ``` - Результат показывается в правой колонке вместо дефолтной "мысли" ### 4.3. История диалога - **Одна общая история** для всех персонажей (один guid) - При переключении: история не очищается, но system prompt меняется - **Риск:** контекст прыгает (отец говорил с "рыбаком", переключился на "Есенина" — история про рыбалку остаётся) - **Решение:** при переключении backend добавляет системное сообщение в историю: ``` [Система]: Собеседник сменился на "Сергей Есенин". Продолжайте разговор. ``` - Альтернатива: при переключении начинать новую "ветку" (но в том же guid) — сложнее --- ## 5. API эндпоинты ### 5.1. GET /api/bookmarks/{guid} - Возвращает список закладок + активную - Response: `{"bookmarks": [...], "active": "default"}` ### 5.2. POST /api/bookmarks/{guid} - Создание новой закладки - Request: `{"description": "Сергей Есенин, поэт, говори поэтично"}` - Логика: поиск → генерация промпта → сохранение файла → добавление в bookmarks.json - Response: `{"bookmark": {...}, "prompt": "..."}` ### 5.3. PUT /api/bookmarks/{guid}/{bookmark_id} - Переключение активного персонажа - Response: `{"active": "esenin", "thought": "«Поэзия — это прогулка в саду души»"}` ### 5.4. DELETE /api/bookmarks/{guid}/{bookmark_id} - Удаление закладки (нельзя удалить "default") - Response: `{"deleted": true}` --- ## 6. Модерация описаний **Проблема:** отец может написать "друг Вася, который пьёт со мной" — бот будет поощрять алкоголь. **Решение:** фильтр на этапе создания закладки: 1. После ввода описания backend проверяет через LLM: ``` System: "Проверь описание на запретные темы: алкоголь, наркотики, насилие, суицид. Если есть — отклоняй." User: [описание пользователя] ``` 2. Если LLM возвращает "отклонить" — показываем отцу: "Это описание не подходит. Попробуйте другого персонажа (писатель, актёр, историческая фигура)." 3. Если "ок" — продолжаем создание **Альтернатива:** белый список тем ("писатель", "актёр", "музыкант", "историческая фигура", "вымышленный персонаж") — жёстче, но безопаснее. --- ## 7. Лимиты - **Максимум закладок:** 10 (чтобы не перегружать UI и не тратить токены на генерацию) - **Максимум размер промпта:** 500 слов (иначе system prompt съест контекст) - **Частота создания:** не чаще 1 в минуту (защита от спама) --- ## 8. Интеграция с основным ТЗ ### 8.1. Изменения в UserSession ```python class UserSession: guid: str active_bookmark: str = "default" # ID активной закладки history: list[dict] profile: str last_response_time: datetime need_compress: bool ``` ### 8.2. Изменения в логике запроса к LLM - При формировании system prompt: - Если `active_bookmark == "default"` → базовый промпт из ТЗ - Если `active_bookmark == "esenin"` → читаем `prompts/персонаж_01.md` - "Умная мысль" генерируется под активного персонажа ### 8.3. Хранение - Директория `prompts/` — файлы промптов персонажей - Файл `bookmarks.json` — список закладок - Всё в той же папке сессий (`sessions/<guid>/`) --- ## 9. План реализации (дополнение к основному ТЗ) **Этап 8: Закладки с персонажами** 1. UI: правая колонка — список персонажей + кнопка "Добавить" 2. Backend: эндпоинты `/api/bookmarks` 3. Логика создания: Yandex Search → LLM → файл промпта 4. Модерация описаний (фильтр на алкоголь/наркотики) 5. Переключение персонажей (смена system prompt) 6. Генерация "умной мысли" под персонажа 7. Тест: создать Есенина, переключиться, поговорить --- **Конец дополнения**
